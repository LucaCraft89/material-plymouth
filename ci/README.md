# CI

`.github/workflows/ci.yml` runs on every pull request and on `main`. The plan behind it (four tiers, all five distros) is `docs/plans/plymouth.md` in [material-grub](https://github.com/LucaCraft89/material-grub); this is what exists so far.

| Job | Tier | What it proves |
|---|---|---|
| Lint | | `ruff` (check and format), `shellcheck` and `actionlint`. |
| Unit tests (Python 3.8 and 3.13) | 1 | The repository's own tests, and the **contract** with material-grub: a checkout of material-grub (`MATERIAL_GRUB_REF`, see the top of the workflow) must have the plugin API this part is written for (`tests/test_contract.py`; a missing or incompatible one fails the job). |
| Consistency with GRUB (built package) | 1 | Builds material-grub's package from the same ref and runs the whole suite with `REQUIRE_CORE=1`: the Plymouth layers are pixel-identical to GRUB's own drawing (hero, title, pills, cookie, logo, background shapes), and every customisation reaches them (distro colours, one seed colour, names, icons, `COOKIE`, `LOGO`, screen sizes). Locally: build the package in a material-grub checkout (`python scripts/package.py --res 1920x1080`) and run the tests with `MATERIAL_GRUB` pointing at it; without a package those tests skip. |
| Plymouth in Xvfb (the theme and the harness) | 2 | `ci/xvfb_play.sh` plays a theme with Plymouth's X11 renderer under Xvfb and takes screenshots; `ci/check_frames.py` checks they are the right size, not blank, and (for an animated theme) that something moves. It runs on Ubuntu's stock `spinner` theme to prove the harness, then `tests/test_theme_play.py` plays the Material theme in every style and motion level and checks the screen: it draws, it moves (or is still with `PLYMOUTH_MOTION=off`, and `calm` and `off` cost less CPU than `full`), `COOKIE`, `LOGO`, a distro colour and the one seed colour reach the pixels, the disk-password prompt takes input (`PROMPT=1`: dots as you type, back to the bar after Enter, the answer reaches the asker) and shutdown mode (`PLY_MODE=shutdown`) shows its message. Screenshots are the `xvfb-screenshots` artifact. |
| Distro probe (Fedora, Ubuntu, Debian, Arch, openSUSE) | 3, first part | `ci/probe-distro.sh` installs Plymouth and the initramfs tooling in a fresh container and writes down what is really there: package names, the script plugin, the initramfs integration (dracut, initramfs-tools or mkinitcpio), how the default theme is chosen, the Python version. It fails when an essential is missing. The report is in the job summary and an artifact. |
| Real initramfs (Fedora, Ubuntu, Debian, Arch, openSUSE) | 3 | `ci/initramfs-e2e.sh` installs Plymouth, the distro's initramfs tool and a real kernel in a fresh container; `ci/initramfs_e2e.py` runs `plymouth apply` and `remove` for real: the image holds the theme, the script plugin and the pictures (listed with `lsinitrd`, `lsinitramfs` or `lsinitcpio`; the theme script inside is byte-identical to the installed one), `--if-changed` rebuilds nothing, a failing tool and a tool that writes broken images both roll back to byte-identical images, theme directory, default theme and config, and `remove` takes it all out again. Not covered: booting the image. |
| Boot in QEMU (Fedora, Ubuntu, Debian, Arch, openSUSE) | 4 | `ci/qemu/prepare.sh` applies the theme in a distro container with a real kernel and the distro's own initramfs tool (dracut, initramfs-tools, mkinitcpio) and builds a test initramfs the same way plus one early hook (`ci/qemu/mgtest-hook.sh`); `ci/qemu/boot.py` boots kernel and initramfs in QEMU (KVM on the runner) and checks, through the serial port and QMP: plymouthd stays up (a crash prints a backtrace that looks like a drawn screen, so the process is checked, not only the pixels), every frame is the theme and not a black text screen (an emergency shell would be one), the splash animates, the disk-password prompt shows a dot per key and removes one on backspace, the typed password reaches the asker, shutdown mode shows its message. Plymouth generations covered: 22.x (openSUSE), 24.x (Debian, Ubuntu), 26.x (Fedora, Arch). Screenshots are the `qemu-<distro>-screenshots` artifacts. The **hand-over** (`ci/qemu/handover.py`): the same kernel and initramfs booted through GRUB under UEFI (OVMF) with material-grub's own theme and an entry titled like the system: the menu is themed and fills the screen, the splash that follows has the same resolution (`gfxpayload=keep`), is the theme, animates, and has the menu's background and hero-card colours. Not covered: a real root file system, a real GPU or panel, real firmware. |
| Package rpm, deb, arch | 3 | `ci/package-test.sh` builds each package from this checkout in a Fedora, Debian or Arch container and exercises it: the package holds the code, the entry file, the hook and the plugin manifest where material-grub looks (and no prebuilt theme); **installing it changes nothing about how the system boots** (no state file, no call to material-grub); an upgrade re-applies only a theme that was applied before, with `--if-changed --no-cmdline` and never the kernel command line; removing it takes the theme out first (`plymouth remove --yes`) and leaves no file of ours. A fake `material-grub` records what the scriptlets call. Not covered: installing next to a real material-grub package (there is none to install yet), signing, a repository. |
| CI passed | | One name for branch protection to require. |

**Not here yet**: the consistency matrix against material-grub, and the upgrade matrix.

## Running it locally

```sh
pip install ruff shellcheck-py actionlint-py pillow pyyaml
ruff check . && ruff format --check . && shellcheck -x --severity=warning ci/*.sh && actionlint
MATERIAL_GRUB=../material-grub REQUIRE_CONTRACT=1 python3 -m unittest discover -s tests -v
# the harness and the played theme (needs plymouth, xdotool, plymouth-x11, plymouth-theme-spinner, xvfb, imagemagick, bc; it links the theme into /usr/share/plymouth and writes
# /etc/plymouth, so use a throw-away machine or container)
ci/xvfb_play.sh spinner build/xvfb/spinner 6 && python3 ci/check_frames.py --size 1920x1080 --moving build/xvfb/spinner-*.png
```

The material-grub ref: the `material_grub_ref` input of a manual run, else the repository variable `MATERIAL_GRUB_REF`, else the default in the workflow (the branch with the plugin API until it is merged into material-grub's `release/0.8.0`).
